# Catalog and revocation fixtures

Made once on Windows 11 with OpenSSL 3, signtool and makecat (Windows SDK
10.0.19041); the bytes are kept, not regenerated by the build.

- `root.der`: "Doors Trust Test Root" (RSA 2048, 2024-01-01 to 2044-01-01),
  keyCertSign and cRLSign.
- `publisher.der`: "Doors Catalog Publisher", serial 0x5011, 2025-01-01 to
  2035-01-01, codeSigning only, CRL distribution point
  `http://10.0.2.2:28480/doors-trust-test.crl` (the host as QEMU's user
  network shows it to the guest). "Doors Revoked Publisher" (serial 0x5012)
  is the same but revoked.
- `doors-trust-test.crl`: the root's CRL (`openssl ca -gencrl`), thisUpdate
  2026-01-01, nextUpdate 2036-01-01, listing 0x5012 as revoked on
  2026-03-01 (keyCompromise).
- `signed-good.exe`, `signed-revoked.exe`: `../unsigned.exe` signed with
  `signtool sign /fd SHA256 /f <publisher>.pfx /p doors` (no timestamp).
- `doors-trust-test.cat`: `makecat doors-trust-test.cdf` over
  `../unsigned.exe` (as `hello.exe`) and `readme.txt`, then
  `signtool sign /fd SHA256` with the catalog publisher. Version 2
  (`CatalogVersion=2`, `HashAlgorithms=SHA256`): each member by its SHA-256
  with an SpcIndirectDataContent attribute, and a SHA-1 entry beside it.

No certificate went into a Windows certificate store: signtool read the
keys from `.pfx` files.
