# Repository layout

Every directory holds one layer of the system. New code goes into the layer it
belongs to; a new top-level directory or crate is added only together with the
code that needs it.

| Directory | Contents |
|---|---|
| `boot/` | UEFI loader (`uefi`), boot configuration (`config`), serial debug encoder (`debug`) |
| `kernel/` | Kernel executive, memory, scheduler, drivers, kernel linker script |
| `runtime/` | Native user runtime: system ABI (`abi`), syscall layer (`sys`), process runtime (`rt`), userland library (`userland`), application linker script (`linker/application.ld`) |
| `fs/` | Storage engine (`storage-core`), initial file system image (`initfs`), file operations (`file-ops`) |
| `crates/` | Shared protocol and format libraries used across layers: `boot-protocol`, `image-format`, `service-protocol`, `shells` (cmd.exe and Doorsh engines), `tls` |
| `services/` | System services process and its `audio` and `network` subsystems |
| `graphics/` | Compositor (`compositor`) and the trusted window server (`window-server`: shell, taskbar, Start, search, User Account Control) |
| `frameworks/` | Libraries apps build on: UI toolkit (`ui`, `app-ui`), `text`, `design-tokens`, `accessibility`, `locale`, `keyboard-layouts`, `service-client`, `settings-map`, `settings-registry` |
| `desktop/` | Desktop applications: `workspace` (File Explorer, Terminal, Settings, Notes), `shell`, `system-monitor`, `preview`, `inbox`, `ime`, `component-gallery` |
| `apps/` | Native command-line programs (`shell`, `tools`) installed under `/system/bin` |
| `compat/` | Windows compatibility: PE loader (`pe`), Win32 ABI (`abi`), DLLs (`dlls/*`), GUI bridge (`gui`) |
| `tests/` | Native test programs (`fixtures`), shared test support (`support`), Windows test programs (`windows-fixtures`) |
| `tools/xtask/` | Build, image, guest-run and verification tool (`cargo xtask …`) |
| `assets/` | Fonts, icons, cursors, sounds, wallpapers, branding, with per-asset provenance |
| `profiles/` | Build, hardware and Windows reference profiles |
| `specs/` | ABI and contract specifications, dependency records |
| `project/` | Roadmap, status, phases, requirements, handoff |
| `docs/` | Architecture decisions (`adr`), build, design, testing, audits, references |
| `third_party/` | Unmodified upstream sources with their licenses |
| `reports/` | Run evidence (`runs`), reviews (`critics`), retained artifacts (`artifacts`); generated |
| `out/`, `target/` | Build output; generated |

## Rules

- Crate directory names describe the component; package names keep the
  `door-` prefix (`frameworks/text` is `door-graphics-text`).
- A library used by more than one layer belongs in `crates/`; a library only
  apps use belongs in `frameworks/`.
- Path dependencies are relative (`../../runtime/abi`), so moving a crate means
  updating its `Cargo.toml` and every dependent's.
- `reports/source-snapshot.json` is regenerated by each `cargo xtask` run; do
  not edit sources while a build or guest run is in progress.
