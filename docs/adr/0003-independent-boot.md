# ADR 0003: independent boot with owned mappings and explicit diagnostics

Status: adopted for P02. Owner: project engineering.

Use original loader/kernel logic in canonical `boot/uefi` and `kernel` destinations.
Reuse the checked boot/image parsers and add a reusable constrained initfs library.
Adopt pinned `uefi` without allocator/logger/panic features for firmware ABI/protocol
glue and the audited final-map/exit operation. SHA2 force-soft supplies content
identity. General firmware glue is not an adopted foreign OS loader/kernel.

Guest binaries opt into narrowly reviewed unsafe hardware/assembly boundaries and
deny unsafe operations without explicit blocks. Portable parsers and host tooling
retain the workspace unsafe prohibition. Feature-required binary targets keep guest
entry/panic paths out of host workspace tests; guest Clippy and builds are explicit.

Build real PE/ELF artifacts, retain ELF symbols and link maps, inspect actual imports,
segments and classes, and compare two exclusive output directories. Firmware LLD's
default PDB identity changed across output paths even with a stable reference name;
disable firmware debug metadata explicitly for this release diagnostic profile.
Kernel symbols/maps remain available. Do not normalize or rewrite generated bytes
to conceal a reproducibility failure. A separate firmware debug profile is future work.

Use bounded 4 KiB page tables for just live boot resources and a guarded high stack,
rather than an all-RAM writable executable identity map. Keep loader/map pages
reserved until P03 adds explicit reclamation. This costs 256 KiB of table storage
and avoids a bootstrap heap, while retaining separate execute/write permissions.

Actual QEMU integration found read-only IDE media rejected on the selected build,
and `-no-shutdown` prevented debug-exit completion. Use read-only virtual FAT through
VirtIO for firmware access and permit diagnostic exits. A raw-disk conversion trial
was superseded and its helper code removed; failed evidence remains preserved.
No native VirtIO driver or installable disk claim follows from firmware reading it.

The visible kernel console uses original glyphs and simple framebuffer drawing.
Local QMP drives diagnostic keys and captures real guest screens. Keep networking
disabled in the guest; the QMP endpoint is loopback host control, UUID-bound for stop.
No shell/desktop is impersonated. Broader UI, input transports, security, exceptions,
allocators, persistence, interrupts/SMP and real userspace remain their later gates.

Acceptance: complete host/target checks, matching inspected guest artifacts, normal
post-firmware completion, malformed handoff/kernel/archive rejection, panic/timeout,
all four diagnostic controls and independent critic replay. Revisit at P03 ownership
retirement, new hardware/host/firmware, secure/release profiles or interactive userland.
