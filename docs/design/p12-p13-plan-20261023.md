# P12 completion and P13 plan (23 October 2026)

Working plan for the owner's request to complete P12 (Native UI, text and
accessibility) and implement P13 (Windows GUI integration). It records the owner
decisions, the audited gaps and the workstream ownership. Agents read this before
editing and keep to their file ownership.

## Owner decisions (23 October 2026)

1. **Historical evidence.** The owner states that P00–P11 were completed and their
   reports deleted for disk space; re-run only where strictly necessary. The gate
   gains an explicit `evidence_unavailable_owner_confirmed` disposition for passed
   phases: original run IDs and critic files stay as historical identity, nothing is
   recreated under old IDs, and the cumulative P12/P13 verification re-executes the
   inherited mandatory commands and guest scenarios on current source (it already
   does so cumulatively). Recorded in an ADR and in `AGENTS.md`.
2. **Fonts.** Use the owner's installed Windows fonts (Segoe UI / Segoe UI Variable,
   Segoe UI Emoji, Segoe UI Symbol, Microsoft YaHei, Yu Gothic, Malgun Gothic and
   others as needed) for this private build. Read-only copies from `C:\Windows\Fonts`;
   provenance records "owner-local, not redistributable"; never published. Fonts load
   at runtime (initfs shared sections), not `include_bytes!`.
3. **Input.** Keyboard layouts (physical/logical keys, AltGr, dead keys, compose) plus
   Chinese Pinyin, Japanese and Korean input methods using openly licensed
   dictionaries, with licences recorded.
4. **P13 reference runs.** Allowed: small Windows test programs may briefly open
   windows on the owner's desktop. No input injection, no setting changes.
5. **Fractional scaling.** Approved: Windows-identical proportions (owner laptop is
   2560×1600 at 150% = 1707×1067 logical).
6. **Phases.** P12 and P13 proceed together.

Defaults chosen without asking: standard Unicode crates (segmentation, bidi, line
breaking, shaping) recorded in `specs/sources/dependencies.json`; the screen reader
publishes a semantic tree with a caption/inspector client now and speech after audio
(P15); touch, pen, controllers, multi-monitor and HDR are recorded exceptions on the
QEMU profile.

## P13 design summary (from the 23 October scoping)

Spec: phase row 2648; WIN-GUI 4220; GUI-E 1366; §54 1259–1273; §107.3 3725–3729;
§108 3742–3745; §136.3–136.4 4671–4682; scenarios 141.5 (5285) and 141.6 (5289).

- New compatibility DLLs: `user32` (window manager, queues, input, controls, menus,
  dialogs, MessageBox, accelerators), `gdi32` (handles, DCs, raster ROP2/ROP3, DIBs,
  text via door-graphics-text), `comdlg32` (Open/Save over kernel32 directory APIs),
  `comctl32` subset. Missing exports fail to load; no success stubs.
- Host-testable portable core `compat/gui` (regions, DLGTEMPLATE/MENUTEMPLATE
  parsers, message ordering, ROP evaluator).
- HWNDs are user32-local generational handles. Top-level, owned and popup windows map
  to native windows; children are client-side inside the top-level surface. One
  connection per process; per-thread queues; no locks across callbacks; bounded
  nested sends; cross-thread SendMessage with reply events; SendMessageTimeoutW and
  IsHungAppWindow; hung windows contained by the server close deadline.
- Paint: per-window update regions; BeginPaint/EndPaint on a private 32-bpp back
  buffer; band COMMIT with alpha forced opaque.
- Loader/personality limits to lift: subsystem 2, resource/load-config/delay-import
  directories, module and run limits, bootstrap DLL records, GUI manifest and heap,
  bulk checked copy.
- kernel32 additions: Heap/Global/Local, Find*File, attributes, file pointer, current
  directory, module file name, startup info, MulDiv, lstr*W, MultiByte/WideChar,
  resources.
- Window-protocol additions: owned/modal role, client-initiated move/resize bound to a
  press serial, geometry change event, size constraints, Unicode titles.
- Fixtures (no CRT, `/SUBSYSTEM:WINDOWS`): F1 self-test, F2 Notepad-like editor (+ RC
  variant), F3 hang. Windows reference run of F1 with identical binary hashes; Door
  guest runs with real QMP input, raw-disk audits and coexistence with native apps.
- Desktop launch of .exe from Explorer through Init EXECUTE.
