# P14 plan: complete desktop and visual fidelity (26 October 2026)

Authorization: owner decision of 26 October 2026 (ADR 0020), recorded as the
P14 `parallel_authorization` in `project/phases.json`. Contract:
`specs/contracts/desktop-shell-v1.md`. Audit basis: the P14 read-only audit of
26 October 2026 (scope, state, risks).

## Exit criteria (specification :2649)

Declared shell surfaces pass interaction and fidelity tests; shell recovery and
real persistent operations pass. Gate: `cargo xtask verify --phase P14`, which
re-executes all of P13 and P12 and then the six `desktop` suites. P14 cannot
pass before P12 and P13; P13 is recorded as passed only on a confirmed report.

## Interfaces between workstreams

1. **Runners (WS-A, WS-B -> WS-C).** Each suite runner is `fn(&mut Run, &str,
   &str) -> Result<Value, String>` in the owner's module
   (`tools/xtask/src/desktop/p14_shell.rs`, `p14_recovery.rs`, `p14_files.rs`,
   `p14_apps.rs`). Report the function; WS-C adds the `desktop::*_suite`
   wrapper and the `scenarios::RUNNERS` entry. Every runner must sign in through
   the launch helpers (they answer the credential gate with the test PIN).
2. **Phase commands (WS-A, WS-B -> WS-C).** The P14 command list already names
   `door-desktop-shell` (guest clippy, `native`), `door-file-ops`,
   `door-settings-registry`, `door-settings-map` (guest clippy and host tests)
   and `door-design-tokens`. Report any further package or test filter.
3. **Credential storage (WS-B).** Provision `/state/credentials` (owner uid 2,
   integrity 2, single `User(2)` full-access entry, no `Everyone` read) at
   volume initialization and at mount of existing volumes. Until then the
   credential store is volatile (`persisted=0`).
4. **Lock and shell (WS-A).** The gate already receives all signed-out and
   locked input (`input.rs`) and repaints the lock card (`present.rs`). Remove
   the bypassed `lock_key`, `lock_button` and `unlock` from `desktop.rs`; keep
   `lock()` (Win+L) as the entry point; the extracted shell must not draw or
   receive input while `shell.locked`, and a shell restart must not unlock.
5. **Tokens (WS-A, WS-B).** Migrate `desktop/workspace/src/tokens.rs` and the
   window-server palettes to `door_design_tokens` accessors; draw the door mask
   in the Start slot at 28 logical px.
6. **Protocol (WS-A -> WS-C).** On completion, report the final shell and
   notification protocol; WS-C finalizes contract sections 2 and 3.

## Order

1. WS-C schema, suites, records (done 26 October 2026).
2. WS-A and WS-B in parallel; WS-C reference, tokens, mark, harness, entropy,
   credential store and sign-in (done host-side 26 October 2026).
3. Register the remaining runners; calibrate VIS-01 probes and record the Start
   motion reference sequence; first guest runs of every suite.
4. Frozen-tree `cargo xtask verify --phase P14`, critic review bound to the
   report, then records.

## Known gaps (26 October 2026)

- No P14 suite has run in a guest; four runners are unregistered.
- VIS-01 motion fails closed until a reference Start-open sequence exists; its
  guest probes are uncalibrated.
- Credential persistence waits for the storage provisioning above.
- The guest CPU model has no RDRAND/RDSEED; jitter health under TCG/WHPX is
  unproven until `sec-02-trusted` runs.
