Spec: section 27 (networking, Winsock, DNS, secure transport), section 28
(audio, multimedia, capture), acceptance CONNECT-A and SOUND-A
(`DOOR_OS_MASTER_SPECIFICATION.md` 4223-4224), exit evidence row P15 (2650):
controlled network and sound scenarios with cancellation, denial, malformed
input and device loss. P15 cannot pass before P12-P14.

settings and GUI (Settings > Network & internet, quick settings, Preview

working implementation exists.

## Architecture and integration points

Kernel (polled, single-CPU device profile, like the data disk):
- `kernel/src/drivers/pci.rs`: `discover(id)` (generic; `NET`, `SOUND`),
  `Function` keeps its id.                                         **done**
- `kernel/src/drivers/virtio_pci.rs`: `Transport::new_sized`,
  `initialize_queues(required, rejected, &[QueueLayout], notify)`,
  `device_config`, `notify_queue`.                                 **done**
- `kernel/src/drivers/virtio_net.rs`: rx/tx split rings, 64 x 2 KiB
  buffers each, VERSION_1|MAC|STATUS, `send`/`receive`/`mac`/`link_up`,
  host tests that play the device.                                  **done**
- `kernel/src/net_device.rs` (to add): like `block_device.rs` — optional
  NIC session: BARs at 0xffff_ffff_b900_0000 (1 MiB stride), DMA at
  0xffff_ffff_ba00_0000 (`virtio_net::DMA_PAGES`).
- `kernel/src/platform_device.rs`: `Owner.nic: Option<NetSession>`;
  `net_info`/`net_send`/`net_receive` with
  `authority(identity, manifest::NETWORK, capability::NETWORK)`.
- `kernel/src/process/platform/calls.rs`: arity table and dispatch for
  `op::NET_INFO` (0x830), `NET_SEND` (0x831), `NET_RECEIVE` (0x832); later
  `AUDIO_*` (0x840..).
- `kernel/src/process/platform.rs`: image lookup for the new service
  manifests (as `ACCESSORY_IMAGE_PATHS`), startup name.
- `runtime/abi/src/platform.rs`: `manifest::NETWORK` (29), `AUDIO` (30),
  `capability::NETWORK` (32), `AUDIO` (64), policies in `manifest_policy`,
  `NetInfo` encoding; `runtime/sys` wrappers.

Services:
- `services/src/network.rs` + `bin/network.rs` (`door-network`): smoltcp
  0.12 (0BSD; features alloc, medium-ethernet, proto-ipv4, proto-dhcpv4,
  proto-dns, proto-ipv4-fragmentation, socket-tcp/udp/icmp/dhcpv4/dns)
  over the NIC syscalls; DHCP lease, static override, DNS with bounded
  cache, routing; socket authority with per-process quotas;
  `door_service_protocol::net` (create, bind, connect, listen, accept,
  send, receive, shutdown/half-close, close, poll, cancel); status for
  Settings. Registered in `service-protocol/src/manifest.rs` (`SERVICES`,
  `CONTRACTS`, `IDS`), `tools/xtask/src/build/native.rs`, `build.rs`
  binaries list and `profiles/build/initfs-*.json`.
- VPN: WireGuard (Noise IK with X25519, ChaCha20-Poly1305, BLAKE2s) as a
  tunnel interface inside door-network, keys in the credential store;
  RustCrypto crates after review (x25519-dalek, chacha20poly1305, blake2).
- `services/src/audio.rs` (`door-audio`): virtio-sound PCM, mixer s16le
  stereo 48 kHz, shared-memory rings, per-stream and session volume,
  underrun/overrun accounting, capture brokered and revocable.

GUI:
- Settings > Network & internet (status, Ethernet properties, DNS, proxy,
  VPN add/connect, data usage, airplane mode = adapter down), quick
  settings network tile and volume slider with level glyphs, taskbar
  network and volume icons, Weather fetching once DNS/TCP (and TLS) work.
- Preview media: WAV and FLAC (own decoders), MP3 (patents expired 2017),
  Ogg Vorbis/Opus as decoders land; MP4/MOV/MKV containers with metadata
  and Motion-JPEG frames; H.264/HEVC decoding stays out (licensing review);
  archives: ZIP (deflate via the existing zune-inflate), TAR, GZ; RAR
  listing from the documented RAR5 headers (no unrar code).
- Run and Settings: entries that work stop saying "Unavailable".

Acceptance (xtask): CONNECT-A (DHCP lease, DNS answer and NXDOMAIN, TCP
echo bytes, half-close, cancel, connection loss, malformed frames) and
SOUND-A (sample-exact playback through the wav backend, two streams mixed,
underrun, denied capture, device removal).

## Order

1. NIC driver (done) → net_device + syscalls → door-network with DHCP/DNS
   → sockets protocol → CONNECT-A.
2. Settings/quick settings/taskbar network UI; VPN.
3. virtio-sound → door-audio → volume UI → SOUND-A.
4. Preview media and archive formats; Winsock and waveOut adapters.

- **`crates/wireguard` (door-wireguard, no_std, sans-IO)**: BLAKE2s HASH,
  keyed BLAKE2s MAC, HMAC-BLAKE2s KDF, ChaCha20-Poly1305 with the 64-bit
  counter nonce, XChaCha20-Poly1305 cookies, X25519 (pinned RustCrypto and
  x25519-dalek already in the tree; blake2 =0.10.6 was already recorded for
  Argon2). Noise_IKpsk2 initiation/response in both roles with mac1/mac2
  and cookie replies; TAI64N stamps (whitened as wireguard-go does) and
  replay/flood refusal of initiations; the previous/current/next keypair
  rotation; transport data with padding, an 8128-counter replay window and
  cryptokey routing on receive; staged packets; the section 6 timers
  (retransmit with jitter, give-up after REKEY_ATTEMPT_TIME, keepalive,
  new handshake after 15 s unanswered, rekey on age/count, last-minute
  rekey on receive, persistent keepalive, key zeroing after 540 s); wg-quick
  parse/export with WireGuard for Windows' error wording (IPv6 entries are
  reported and left out: the stack is IPv4); IPv4 helpers and TCP MSS
  clamping. 30 host tests, including the construction constants and an
  interop suite against boringtun 0.7.1 (host-only dev-dependency, owner
  approved): Doors and boringtun each as initiator, with and without a
  preshared key, every size up to the MTU, a mid-session rekey from
  boringtun, a wrong peer key.
- **door-network (`services/network/src/vpn.rs`)**: connections per user
  (`net::vpn` STAGE/SAVE/REMOVE/CONNECT/DISCONNECT/ENTRY, opcodes
  0x6020-0x6025; Settings and Terminal edit their own user's, the window
  server reads and dials for the user of its session). Connecting resolves
  the server, handshakes over a UDP socket bound to the adapter's address,
  and only after the first handshake adds the tunnel address to the
  interface. The NIC then diverts frames sourced from the tunnel address
  into the tunnel (MSS clamped to MTU-40), answers ARP for on-link tunnel
  peers, and delivers decrypted packets as Ethernet frames. New sockets get
  an explicit source: the tunnel's where the peer's AllowedIPs route the
  destination (longest prefix vs. the on-link network unless the
  kill-switch is on), the adapter's otherwise (smoltcp 0.12 would pick the
  first address). Only AllowedIPs destinations are sent to the peer. The
  tunnel's DNS servers replace the adapter's while up. 0.0.0.0/0 turns on
  WireGuard for Windows' kill-switch: physical traffic other than DHCP and
  the tunnel's own datagrams is dropped. Failures are truthful: no network,
  server name unresolved, no handshake within 15 s. Kernel: ENTROPY_READ is
  also granted to the NETWORK capability (served from the apps' DRBG) for
  ephemeral keys and indices.
- **Terminal (cmd)**: `rasdial` (list, dial, `/disconnect`, rasdial.exe's
  texts and Remote Access errors 623, 800, 809 and 868 as exit codes) and
  WireGuard for Windows' `wireguard /installtunnelservice <file.conf>` /
  `/uninstalltunnelservice <name>` (tunnel names per WireGuard's rule).
- **Quick settings**: the VPN tile and page list the session user's
  connections (Connected / Connecting… under the name; Connect, Cancel or
  Disconnect), refreshed every 3 s, every second while open.
- **Settings > Network & internet > VPN** (Page 58): "VPN connections" with
  Add VPN (dialog "Add a VPN connection": connection name and the
  provider's WireGuard .conf, validated with the provider's error text),
  and each connection with its status, Connect/Disconnect and Remove.
- **VPN-A** (`tools/xtask/src/desktop/p15_vpn.rs`,
  `tests/fixtures/windows-net/vpnprobe.c`): boringtun on this host behind a
  host smoltcp stack at 10.8.0.1 (TCP/UDP echo, DNS for vpn.doors.test,
  ICMP). In Terminal: the .conf files typed with ECHO, `wireguard
  /installtunnelservice office.conf` (first handshake 10 ms), `rasdial`;
